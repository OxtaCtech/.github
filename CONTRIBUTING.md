# Contributing to OxtaCtech

Thank you for contributing.

1. Open a structured Issue describing the problem, expected behavior, affected components and acceptance criteria.
2. Link implementation work to the corresponding Issue or architecture decision.
3. Create focused Pull Requests with tests, observable outcomes, limitations and a rollback strategy where relevant.
4. Keep personal data, API credentials, financial records and production logs out of public Issues, pull requests and artifacts.
5. Address code review and CI findings; passing automation alone does not constitute homologation.
6. Respect repository-specific policies and code ownership.

Security reports must use the private channel specified by the affected repository.
